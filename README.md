# QA Software Testing Portfolio

Portfólio de Quality Assurance (QA) com foco em testes manuais, testes funcionais, testes de regressão, análise de defeitos e documentação de resultados.

## 🎯 Objetivo

Documentar meus estudos e práticas em qualidade de software, demonstrando como estruturo cenários de teste, valido funcionalidades, comparo resultados e registro comportamentos inesperados.

Os estudos de caso são apresentados de forma demonstrativa, com dados fictícios e sem exposição de informações confidenciais.

## 🧪 Competências exploradas

- Elaboração e execução de casos de teste
- Testes funcionais manuais
- Testes de regressão
- Validação de relatórios e exportação para Excel
- Testes de processamento e importação de arquivos
- Validação de fluxos de autorização por QR Code
- Testes funcionais de notificações por e-mail
- Registro e análise inicial de defeitos
- Documentação de evidências e resultados
- Análise de cenários positivos e negativos

## 📂 Estudos de caso

| ID | Estudo de caso | Área |
|---|---|---|
| TC001 | Investigação de falha na geração de relatório | Relatórios e defeitos |
| TC002 | Comparação entre relatório em tela e Excel | Consistência de dados |
| TC003 | Validação de relatório, formatação e logotipos | Relatórios |
| TC004 | Processamento de planilha para cadastro em massa | Importação de arquivos |
| TC005 | Geração e direcionamento de QR Code | Fluxo de autorização |
| TC006 | Reenvio e recebimento de notificações por e-mail | Notificações |

*Os resultados, critérios de validação e limitações serão documentados individualmente em cada caso.*

## 🛠️ Ferramentas e tecnologias

- **Postman:** estudos e testes de APIs
- **Selenium:** estudos de automação de testes
- **SQL Server:** consultas e análise de dados
- **Git e GitHub:** versionamento e documentação
- **Python:** estudos de programação e automação

## 📋 Padrão de documentação

Cada caso de teste poderá conter:

1. Identificação e objetivo
2. Pré-condições
3. Dados de teste
4. Passos para execução
5. Resultado esperado
6. Resultado obtido
7. Status do teste
8. Evidências demonstrativas
9. Observações e limitações

## 🔐 Privacidade e confidencialidade

Este portfólio tem finalidade educacional e profissional. Os exemplos públicos devem utilizar dados fictícios e não devem expor dados pessoais, informações de clientes, credenciais, logs internos, código proprietário ou detalhes confidenciais de sistemas.

Qualquer material relacionado a atividades profissionais deve respeitar as políticas da organização e as autorizações necessárias.
